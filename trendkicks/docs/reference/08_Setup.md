# Trend Kicks — Setup Guide

## 1. Purpose

This document is the manual setup guide for the Trend Kicks Flutter e-commerce application.

This document is primarily for the developer/student setting up the project.

It explains:

- What needs to be installed
- What needs to be created manually
- What needs to be configured in Firebase Console
- What commands need to be run in the terminal
- How Flutter is connected to Firebase
- How Firebase Authentication is configured
- How Cloud Firestore is configured
- How Firebase Storage is configured
- How Firebase Security Rules are configured
- How Android and Web development are configured
- How to verify that Firebase is working
- What the developer does manually
- What the coding AI can implement
- What to do when an error occurs

The coding AI must use this document as a setup reference but must not pretend that it has performed manual Firebase Console or terminal actions.

---

The setup process must clearly separate tasks performed manually by the developer from tasks that can be implemented by the coding AI.

### Developer Responsibilities

The developer must manually:

- Create the Flutter project

The coding AI may:

- Create and modify Dart files
- Implement Flutter UI

- Implement services
- Implement repositories
- Implement state management
- Implement Firebase integration code
- Implement authentication logic

- Help troubleshoot errors
- Explain what each configuration step does
- Verify the implementation against the project's MD files

The coding AI must not claim that it personally created a Firebase project, enabled a Firebase service, ran a terminal command, or changed a Firebase Console setting unless the developer actually performed that action through an available tool.

## 7. Firebase Services Required

Trend Kicks will use the following Firebase services:

- Firebase Authentication
- Cloud Firestore
- Firebase Storage

Each service has a different purpose.

### Firebase Authentication

Used for:

- Registration
- Login
- Logout
- Password authentication
- Authentication state
- Identifying the authenticated user

### Cloud Firestore

Used as the primary application database.

It will store application data such as:

- Users
- Products
- Product variants
- Carts
- Orders
- Order items
- Reviews
- Refund requests
- Notifications

The exact data structure must follow `06_DATA_MODELS.md`.

### Firebase Storage

Used for file storage such as:

- Product images
- User profile images
- Other approved application images

Firestore should store the relevant image URL/reference rather than storing the actual image binary data inside normal Firestore documents.

## 14. Registration Behavior

When a new customer registers:

- Firebase Authentication creates the authentication account
- The user is automatically considered a customer
- The application creates the corresponding user profile document in Firestore
- The user should automatically become logged in after successful registration according to the application requirements

The customer must not be able to register as an administrator.

The role should default to:

    customer

Admin accounts are created manually.

## 19. Product Image Storage

Product images should be stored in Firebase Storage rather than directly inside Firestore documents.

The general flow is:

    Flutter
        ↓
    Select product image
        ↓
    Firebase Storage
        ↓
    Image URL/reference
        ↓
    Cloud Firestore
        ↓
    Product document stores the reference

When the application displays a product:

    Firestore
        ↓
    Image URL
        ↓
    Flutter Image Widget
        ↓
    Product image displayed

The coding AI should implement this flow when product management is built.

---

## 20. Profile Image Storage

User profile images should use Firebase Storage.

The general flow is:

    Flutter
        ↓
    User selects profile image
        ↓
    Firebase Storage
        ↓
    Image URL
        ↓
    User document in Firestore

The customer profile document should store the image URL/reference rather than the actual image file.

Storage access must follow `07_SECURITY.md`.

## 21. Firebase Security Rules

Security Rules are required for:

- Cloud Firestore
- Firebase Storage

The security requirements are defined in:

    07_SECURITY.md

Security Rules must prevent unauthorized users from:

- Reading private user information
- Reading another customer's orders
- Modifying another customer's cart
- Modifying product prices
- Modifying product stock
- Changing their own role
- Approving their own refund
- Modifying protected transaction information
- Accessing unauthorized files

The coding AI may help write the rules, but the developer must deploy and verify them.
